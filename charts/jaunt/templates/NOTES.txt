{{- if .Values.ca.init.enabled }}

The Job {{ include "jaunt.fullname" . }}-ca-init runs "jauntd ca init" once. It prints only public data (the CA public keys and the internal root's SHA-256). The daemon pod fails to start until it succeeds and is restarted by the kubelet after it. When it has succeeded, set ca.init.enabled=false on the next upgrade: a second run fails, because the authority already exists.

  kubectl logs -n {{ .Release.Namespace }} job/{{ include "jaunt.fullname" . }}-ca-init
{{- else }}

The certificate authority is created once with "jauntd ca init"; see the README, section First run. The daemon does not start without it.
{{- end }}

The access policy is mounted from {{ include "jaunt.policyConfigMapName" . }} and reloaded without a restart. An empty policy denies everything.

To reach the control port without publishing anything:

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "jaunt.fullname" . }} {{ .Values.service.ports.http.port }}:{{ .Values.service.ports.http.port }}
  curl http://localhost:{{ .Values.service.ports.http.port }}/healthz
